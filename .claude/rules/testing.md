# Rule: Testing

- Real tests live in `tests/HrAutomation.Tests` (xUnit), run via `dotnet test tests/HrAutomation.Tests/HrAutomation.Tests.csproj` against a real `HrAutomationDb` instance (LocalDB), not an in-memory/mocked provider — stored procedures and row-level security don't exist in EF Core's in-memory provider. `HrApiFactory` doesn't isolate a fresh database per run; see DEC-007 in `DECISIONS_REQUIRED.md`. Use a seeded real user/tenant ID (`src/HrAutomation.Infrastructure/Database/seed/03-seed-iam-users-access.sql`) via the dev-token endpoint, not a randomly-generated one — a random tenant/user ID fails the real foreign-key constraints.
- Add tests for every new or changed workflow state transition, including the illegal-transition case (a stored procedure returning `Success = false`/`ErrorCode`, not silently accepting it) — see [ADR-006](../../docs/adr/ADR-006-database-first-stored-procedure-workflow.md) for how transitions are actually implemented; [docs/02-business-workflows/workflow-state-machine.md](../../docs/02-business-workflows/workflow-state-machine.md) describes the original target-state design, not the real mechanism.
- Follow the test pyramid in [docs/09-quality-evaluation/test-strategy.md](../../docs/09-quality-evaluation/test-strategy.md): unit, integration, contract, end-to-end, security, performance, accessibility, chaos/resilience, RAG, agent, MCP, human acceptance — pick the tier(s) relevant to the change, don't skip contract tests for API/event changes.
- Any change to a prompt, model, or RAG configuration requires a pass of the AI evaluation suite in [docs/06-ai-agents-rag/ai-evaluation-strategy.md](../../docs/06-ai-agents-rag/ai-evaluation-strategy.md), including the fairness check and red-team suite where applicable.
- Every test uses fake/demo data only — never real candidate, employee, or client data.
- Never skip CI/CD quality gates ([docs/10-delivery/ci-cd-quality-gates.md](../../docs/10-delivery/ci-cd-quality-gates.md)) or use `--no-verify`-equivalent shortcuts except through the documented, logged emergency-fix process.
- A cross-tenant isolation test is mandatory for any change touching data access or authorization.
