# Rule: AI Agents

- Read [docs/06-ai-agents-rag/agent-architecture.md](../../docs/06-ai-agents-rag/agent-architecture.md) and [docs/06-ai-agents-rag/agent-skill-catalog.md](../../docs/06-ai-agents-rag/agent-skill-catalog.md) before adding or modifying a skill — both now carry an "Implementation reality notice": only CV extraction and the two TAN skills are real, everything else listed is an unimplemented stub in `HrAutomation.Agents/Stubs/`. Check [PROJECT_STATUS.md](../../PROJECT_STATUS.md) for current status before assuming a skill exists.
- A skill is a class implementing `ISkill` in `HrAutomation.Agents`, registered in `Program.cs` and resolved via `ISkillRegistry`. There is no separate "Supervisor Agent" process — `HrAutomation.Api` controllers and `HrAutomation.Application`'s `IWorkflowOrchestrator` dispatch to skills in-process.
- Every skill returns JSON-Schema-validated structured output (`SkillResult`). Never let a skill return free-form text that is interpreted as an executable instruction downstream.
- Every skill call is least-privilege: grant only the specific MCP tools that skill needs, at the narrowest tier (read-only / propose-only / approval-required write) per [docs/07-mcp-integrations/mcp-security-and-authorization.md](../../docs/07-mcp-integrations/mcp-security-and-authorization.md). No MCP tools exist yet (`HrAutomation.Mcp` is an empty scaffold) — this applies once integration work starts.
- No skill may hold a credential capable of writing workflow-state tables directly. All state mutation goes through the stored procedure that owns that entity's transition ([ADR-006](../../docs/adr/ADR-006-database-first-stored-procedure-workflow.md)), which enforces the approval matrix independently of what the skill recommends — never a generic "HR Core API" state-mutation layer (that component was never built).
- Confidence thresholds gate every skill's output (see [docs/05-security-governance/ai-guardrails-policy.md](../../docs/05-security-governance/ai-guardrails-policy.md)); below-threshold results route to human review, never a silent best-guess.
- Any prompt or model change follows [docs/06-ai-agents-rag/prompt-management.md](../../docs/06-ai-agents-rag/prompt-management.md): versioned, peer-reviewed, evaluated against [docs/06-ai-agents-rag/ai-evaluation-strategy.md](../../docs/06-ai-agents-rag/ai-evaluation-strategy.md) (including fairness and red-team suites) before promotion, with a rollback path.
- RAG changes respect [ADR-003](../../docs/adr/ADR-003-rag-and-vector-store-boundary.md): metadata ACL filtering before search, citations required, no-answer fallback on insufficient grounding.
